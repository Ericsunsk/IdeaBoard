# 阶段二：Personal Asset Library Core

状态：已实现

## 目标

为 Search 建立一个可持久化的 Personal Asset Library，用于保存和整理 Unsplash/Pexels 外部素材引用。阶段二解决“保存、归类、查看、移除”这条闭环，并在 Search 提供轻量浮动岛入口；不提前实现视觉分析、Moodboard 或 Canvas 联动。

## 已确认决策

- Library 只通过 Search 页面上的 Floating Island 访问；Folder 状态由浮岛内部 workspace 管理。
- 顶部主导航保持 `Search / Workspace`；Library 通过 Search 搜索栏右侧的圆形入口进入。
- 未来浮动岛只复用本阶段的 data layer 和组件，不改变 Library 数据模型。
- 素材只保存外部 URL 与 Provider/source metadata，不复制到 R2，也不进入 `media_assets`。
- 阶段二只允许 `unsplash` 和 `pexels` 的规范素材引用。
- 一个素材只能属于一个 Folder；移动不是复制。
- `All Assets` 是虚拟视图；`Quick Saves` 是懒创建的系统 Folder。
- 用户 Folder 可创建、重命名和删除；删除时素材移动到 `Quick Saves`。
- 同一用户的 `(provider, source_id)` 全局唯一，重复保存幂等命中并按需移动 Folder。
- 重复保存不覆盖已保存的 title、author、尺寸和 URL metadata。
- Folder 数量实时聚合，不在 Folder 表中存 `asset_count`。
- 列表使用 opaque cursor；默认按 `created_at DESC, id DESC` 排序，每页 24 条。
- 图片使用原生 lazy loading；路由使用 dynamic import；不引入虚拟列表。
- Search 保存使用 Quick Save Popover；输入新 Folder 后，创建 Folder 与保存素材必须在同一 PostgreSQL transaction 中完成。
- Search 页面通过独立 batch lookup 恢复已保存的 `+ / ✓` 状态，不把 Library 状态塞进 Provider Search API。
- Search 页面通过搜索栏右侧 `44×44px` 圆形按钮打开轻量 Library 浮动岛；浮动岛按需加载并复用 Library workspace、Folder、分页、预览和移除能力。
- Library 卡片只保留 Move 和 Remove；`Use as Search Reference` 延后到 Vision Search 阶段。
- Lightbox 严格按 Demo 展示图片、title 和 author，不显示 Provider 或“查看来源”按钮；source metadata 只保存在数据层。
- mutation 采用服务端成功后更新，不做盲目 optimistic mutation。
- 不做 Library SSE/WebSocket、跨视窗拖拽、Library 内关键词搜索、回收站、软删除、下载、编辑、标签、palette、atmosphere 或 Moodboard。

## Domain Model

### `library_folders`

使用项目现有 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 主键。

字段：

- `id`
- `owner_user_id`：引用 `users.id`，用户删除时级联删除
- `name`
- `is_system`
- `is_default`
- `created_at`
- `updated_at`

约束：

- 同一用户 Folder 名称大小写不敏感唯一。
- `All Assets` 不落库。
- `Quick Saves` 由后端按需确保存在，不能重命名或删除。

### `library_assets`

使用项目现有 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 主键。

字段：

- `id`
- `owner_user_id`：引用 `users.id`，用户删除时级联删除
- `folder_id`：引用同一用户的 `library_folders.id`
- `provider`
- `source_id`
- `source_url`
- `preview_url`
- `original_url`
- `title`
- `author`
- `width`
- `height`
- `created_at`
- `updated_at`

约束和索引：

- `UNIQUE (owner_user_id, provider, source_id)`。
- `provider` 只允许 `unsplash`、`pexels`。
- source identity、URL、文本和尺寸必须通过长度、空值和非负值校验。
- URL 必须是 HTTPS，并匹配对应 Provider 的允许 host；服务端不请求用户提交的 URL。
- 按 `(owner_user_id, folder_id, created_at DESC, id DESC)` 支持列表查询。
- 按 `(owner_user_id, provider, source_id)` 支持幂等保存和 batch lookup。

## API Contract

所有 endpoint 位于已认证的 `/api/user` 路由组，使用现有 response envelope 和稳定 `error_code`。

### Folder resources

- `GET /api/user/library/folders`
  - 返回 `All Assets`、`Quick Saves` 和用户 Folder。
  - 每个 Folder 返回稳定 `query_key`：`all`、`quick-saves` 或持久化 Folder ID；前端不得自行推导系统 Folder identity。
  - 顺序固定为：All Assets、Quick Saves、用户 Folder `created_at ASC, id ASC`。
  - count 由 `library_assets` 实时聚合。
- `POST /api/user/library/folders`
  - 创建用户 Folder。
- `PATCH /api/user/library/folders/:folder_id`
  - 重命名用户 Folder。
- `DELETE /api/user/library/folders/:folder_id`
  - 将素材移动到 Quick Saves 后删除 Folder。

### Asset resources

- `GET /api/user/library/assets?folder_id=&cursor=&limit=`
  - 返回 `items`、`next_cursor`、`has_more`。
  - 不返回 `total`。
  - `folder_id` 缺省表示 All Assets；系统 Folder 使用稳定的 query identity。
- `POST /api/user/library/assets`
  - 接收 `folder_id` 或 `new_folder_name` 二选一。
  - `new_folder_name` 与素材幂等保存必须在同一 transaction 内完成。
  - 冲突时不覆盖已有 metadata，只执行幂等命中和 Folder 移动。
- `PATCH /api/user/library/assets/:asset_id`
  - 移动到目标 Folder。
- `DELETE /api/user/library/assets/:asset_id`
  - 硬删除 Library 记录，不影响外部图片。
- `POST /api/user/library/assets/lookup`
  - 批量查询当前 Search 结果中已保存的 `(provider, source_id)`，最多 48 项。
  - 仅返回已保存的 asset/folder identity。

### Error codes

至少包括：

- `library_folder_name_invalid`
- `library_folder_name_conflict`
- `library_folder_system_immutable`
- `library_folder_not_found`
- `library_asset_provider_invalid`
- `library_asset_source_invalid`
- `library_asset_not_found`
- `library_asset_target_folder_invalid`
- `library_cursor_invalid`

前端将 error code 映射为简短用户文案，不展示 SQL、Provider URL 或内部错误详情。

## Frontend Boundaries

阶段二新增 `features/library` feature context，最小拆分如下：

- `resource.ts`：API adapter、cursor、Folder/Asset commands、batch lookup。
- `useLibraryWorkspace.ts`：浮岛的 Folder、分页、Lightbox 和 mutation 状态。
- `LibraryFloatingIsland.vue`：浮岛布局、Folder commands、分页状态和 Lightbox orchestration。

Search feature 只通过 `features/library` 的明确 seam 参与保存和 lookup；不直接依赖 generated API。

状态要求：

- 首次加载使用固定比例 Skeleton，避免布局跳动。
- 切换 Folder 保留旧内容并显示局部 loading。
- 下一页只显示底部 loading。
- 首屏错误保留 Retry；单图错误只影响对应卡片。
- mutation pending 时保持按钮尺寸；服务端成功后更新本地状态。
- All Assets 和空 Folder 提供简短行动型 empty state。

## Testing

### Backend

- Folder CRUD 与用户隔离。
- system Folder 不可变。
- `(provider, source_id)` 幂等保存和冲突移动。
- 新建 Folder + 保存素材的 transaction atomicity。
- Folder 删除回收至 Quick Saves。
- provider/URL/source/尺寸校验。
- cursor 边界、非法 cursor 和排序稳定性。
- batch lookup 不泄露其他用户数据。

### Frontend

- route query 与 Folder 查询同步。
- save/move/remove 状态转换。
- lookup 结果恢复 `+ / ✓` 状态。
- 分页、重试和单图失败状态。
- API adapter contract。

不新增纯文案测试、截图测试或浏览器 E2E；浏览器体验由人工验证。
