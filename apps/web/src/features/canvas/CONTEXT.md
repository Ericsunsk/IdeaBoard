# Canvas Context

Canvas Workspace owns editing a Canvas Board: node orchestration, graph interaction, image task execution, and in-place editing of image results.
It coordinates one Board Session through the Workspace Runtime facade plus Screen, Chrome, Flow Pane, and image workflow modules.
It does NOT own the Board document contract, repository, or sync fact source (owned by `features/board`), nor provider-side task execution.

## Collaboration Session

`session/collaboration` owns the live document lifecycle behind one session interface. The Screen adapts pointer events and consumes presentation state; the session owns the presence provider, ticket rotation, reconnect policy and awareness throttling; Workspace binds the Board context, and Flow attaches its canonical GraphSession adapter after HTTP hydration. Board residency, room readiness, write capability, changed-id synchronization, remote replacement and scope disposal stay inside the session. The synchronized Y.Doc is the remote replay buffer; callers keep no second pending snapshot. Collaborative commits bypass snapshot autosave and remote replacements bypass local commit/history/echo. Private Boards retain the existing snapshot persistence path (ADR-0020).

Document mapping consumes the canonical `board/ports/canvas` contract and validates remote frames there. No screen-owned snapshot schema mirror or caller casts are allowed. Soft locks and awareness presentation stay in `ui/screens/presence`.

## Public Seams

- `useCanvasWorkspaceRuntime()` / `CanvasWorkspaceRuntime` — Workspace Facade runtime in `session/workspace` (via `session/workspace/index.ts`); pages read `runtime.viewModel` and trigger `runtime.commands`; Board/Flow assembly groups `boardSession`, `flowPane`, `graphEditing`, `boardChrome`.
- `CanvasScreen` — screen-level interaction assembly in `ui/screens` (via `ui/screens/index.ts`); CanvasPage passes route, router, user identity, logout integration; Screen uses only the Workspace Runtime public seam.
- `CanvasGraphStore` plus transaction/id/summary types — canonical graph core runtime in `core/graph` (via `core/graph/index.ts`); callers express mutation intents via transaction/summary.
- `useCanvasGraphEditing()` / `useCanvasGraphInteractions()` — complementary graph-intent runtimes in `session/graph-editing` (via `session/graph-editing/index.ts`); creation/file-drop-upload/media-input mutation vs selection/preview/append-export/Alt-drag-duplication; page emits intents via `commands.graphEditing`; Node handlers via one `createNodeInteractions()`.
- `viewModel.flowPane.nodes` / `viewModel.flowPane.edges` plus `commands.flowPane` — Vue Flow adapter boundary in `session/flow-adapter`; `onNodesChange`, `onEdgesChange`, sole `connectionAdapter`, `nodeDragTransactions`; connection adapter public contract lives in `session/flow-adapter/index.ts`.
- `useBoardSession()` / `createBoardSyncCoordinator()` plus `BoardSession` and sync/load/save result types — board open/save/recovery/upload-lifecycle/id-resolution in `session/board-session` (via `session/board-session/index.ts`); Workspace loads/saves through this seam, Graph Runtime applies returned snapshots. Board document facts enter through the pure `features/board/ports/canvas` port; browser persistence, catalog, and sync enter through `features/board/ports/canvasSession`; the autosave save-loop policy (`autosavePolicy.ts`, framework-free) stays separate from the `useBoardAutosave` Vue lifecycle adapter.
- `ui/chrome` — chrome layout shell (via `ui/chrome/index.ts`): Board header, right action/account group, left tool palette, bottom status/zoom, minimap anchoring, geometry, interaction shell; callers pass state/actions, Chrome outputs layout components.
- `createImageExecutionPlanner()` plus feature/action constants, execution contract builders, size/ratio helpers, plan/result types — execution planning boundary in `session/execution` (via `session/execution/index.ts`); an Execution Plan is not a Task or pending UI state.
- `createCanvasTaskLifecycle()` plus `cancelTasks()` — task cancellation policy owner in `session/execution/task-lifecycle/canvasTaskLifecycle.ts`; task id normalization, bounded retry, final failure reporting; delete path cancels only exact-lease task ids.
- `viewModel.imageWorkflow` plus `commands.imageWorkflow` — image workflow deep module in `session/image-workflow`; tools, interactions, `isGenerationAvailable`, `cancelOutpaint`, `hideStrengthControl`; composition root injects graph, execution, Flow Pane, UI adapter, feedback; full Session assembles once inside the workflow.

Library asset drops use the shared Pointer Events controller and explicit Canvas target registration. Screen coordinates are converted through the current Vue Flow transform before `libraryImport.add`; external image files keep native file-drop handling. Board/Workspace changes, editing locks and disposal cancel active drags. Pending preview decode results are discarded when their Board attachment changes. After drop, the original node stays loading while `media_not_found` reads wait with capped backoff for up to 90 seconds. Other errors or timeout produce a failed node with explicit retry. Deletion, Board attachment changes and disposal stop readiness reads.

## Graph Runtime

`CanvasGraphStore` is the normalized graph fact source, independent of Vue Flow. It hydrates/exports the Board snapshot, provides indexed node/edge reads and stable ordered IDs, and owns derived connection/media-input indexes.

`CanvasGraphTransaction` stages mutations without changing committed state, supports cancel, and atomically returns changed/removed IDs, order changes, history intent, and autosave intent. History and autosave consume committed summaries: one logical action creates at most one history entry and one autosave schedule. Viewport persistence is separate from semantic graph changes.

The Flow adapter keeps the complete canonical node/edge set in controlled arrays, preserves unchanged object identities, and applies incremental updates. Viewport changes only update the transform; they never replace graph arrays or trigger graph projection. `onlyRenderVisibleElements` stays disabled to keep connected edges and MiniMap bounds stable.

Canvas navigation uses native Vue Flow pan gestures: Select supports middle/right background panning; Hand supports all mouse buttons. Pane and Group context actions share the native settled right-click callback; Node and non-pannable selection overlays retain local menus. Ctrl-click takes context-menu priority over background panning, including while Space is held. The existing keyboard lifecycle owns temporary Space Hand mode without changing the selected tool; Vue Flow owns movement and its separate activation shortcut is disabled. Scroll pan speed is 1.2, edge auto-pan speed is 15, zoom is clamped to 0.15–2, and double-click zoom is disabled.

Image preview quality uses a central settled zoom snapshot, separate from the live viewport zoom used by geometry and screen-sized controls. Canvas image tiers follow exact unrounded zoom: below 77% uses 256px, 77% to below 138% uses 640px, and 138% or higher uses 1280px. Ordinary navigation never selects original; image tools request it explicitly. Zoom changes publish after an 80 ms idle window that coalesces wheel/pinch bursts; asynchronous programmatic viewport commands also hold the snapshot until completion. Board or user changes invalidate pending movements; disposal cancels pending updates. New images use the available snapshot. Image-tool quality requests share the same settle window and movement locks: previews retain their current tier throughout focus zoom, then select the latest requested tier or original once the viewport settles. Existing delivery cancellation, caching and decode-before-swap remain authoritative.

Screen-sized node controls inherit `--canvas-node-ui-scale` from the Flow surface. Individual node bodies do not subscribe to live zoom to publish their own style; pointer geometry still uses live viewport coordinates. The composing Orb reuses per-context geometry buffers while sorting the animated depth every frame.

Graph snapshot export owns its data. Upload stabilization updates that save-owned snapshot in place, so the Board Sync Coordinator keeps an independent capture for media reconciliation with concurrent edits. Opt-in timing distinguishes graph export, reconciliation capture, stabilization, and the full asynchronous save lifecycle.

Normal stage images crossfade over 200 ms after replacement decode, with a transient outgoing blur of 14px and scale of 1.1. Source changes and tool presentation do not crossfade; reduced motion disables the transition. The outgoing image keeps its decoded DOM frame and a resource pin until Vue finishes its leave transition; no new placeholder request or persistent image plane is created. Image Preview Resources pin displayed frames until replacement decode completes. Obsolete decodes cancel promptly, while Retouch cache disposal aborts pending fetches and releases late bitmaps before further canvas work. Opt-in telemetry distinguishes managed delivery and client fallback, reports bounded timing samples, and separates retained/pinned/reusable resources. Pixel and Blob-byte gauges are estimates of retained image data, not GPU memory measurements.

- Node drag batches native position/selection events per frame and commits the final position once. Renderer-only measurements, geometry, and interaction fields stay outside the controlled domain model.
- Connect normalizes endpoints and creates a canonical `connection-*` ID in one transaction. Endpoints are immutable; repositioning requires delete then connect with independent transaction/history boundaries.
- Native disconnect/delete/batch-delete coalesce into one matching transaction; deleting a node removes its connected edges atomically.
- Corrupt or non-canonical node/edge data produces a visible warning and leaves the graph unchanged.

Graph specs cover snapshot roundtrips, transaction commit/cancel and dirty summaries, drag coalescing, canonical connections, and undoable batch deletion. Benchmark reports remain in the ignored `.benchmark-reports/` directory.

## Invariants

- `viewModel.flowPane.nodes` / `viewModel.flowPane.edges` are Vue Flow binding only (e.g. `const { nodes, edges } = viewModel.flowPane` in `CanvasPage.vue`); never use them for business decisions.
- Pages use `isValidConnection` / `onConnect` only through `commands.flowPane.connectionAdapter`; no independent connection commands.
- Canvas submodules import only the connection adapter public contract from `session/flow-adapter/index.ts`; never deep-import adapter implementation.
- Vue Flow native events and interaction handlers live in `commands.flowPane` (`onNodesChange`, `onEdgesChange`, `connectionAdapter`, `nodeDragTransactions`); connection event shape is not a direct page command.
- Page-layer runtime access goes only through the `useCanvasWorkspaceRuntime()` `viewModel` / `commands` Facade; new page logic never bypasses the Facade for internal modules.
- CanvasPage passes state/actions to the Chrome module; no new route-local chrome geometry classes, no revived legacy positioning variants.
- Chrome module may own minimap anchoring but never minimap math, viewport sync, or graph interaction semantics.
- Graph domain rules live in `board/core` or `core/graph` semantics; Vue Flow specifics stay in the `session/flow-adapter` boundary.
- Coordinator never calls `commitGraph`, replaces renderer snapshots, maintains history baselines, or depends on Vue Flow projections.
- Selection identity may come from the Flow adapter, but preview/export/duplicate facts must read `CanvasGraphStore`.
- Node media/input upload stays out of the graph interaction module; graph interaction never derives facts from Vue Flow `data.snapshotNode`.
- `BoardSnapshot` saves persistence facts only, never Flow Edge `animated`.
- `PendingImageExecutionCore` is the sole Task runtime owner; each board open/switch/reload creates a new opaque attachment epoch; old attachments or superseded leases never mutate the current graph.
- Core state/lease is the sole live-running fact for the current Board; presentation, cancellation, and delete paths read Core capability, never keep running `Ref` / `Set`, pass running callbacks, or infer live state from snapshot `outputStatus`.
- Snapshot `outputStatus: 'running'` plus `pendingTaskId` is a persisted pending-task fact for Hydration only; only Hydration may claim that reattach lease atomically once.
- Whole-graph hydrate, save reconciliation, history restore, and execution transitions recompute all image-input edge animation from the current Core snapshot via the Flow runtime.
- Flow Edge `animated` is an ephemeral projection outside serializer/history/undo-redo contracts; history capture/restore never records or restores it; re-project after each semantic commit.
- Deleting an active execution node resolves task identity from the current Core lease/state; after graph delete succeeds, release the lease and cancel only Core-returned `cancellableTaskIds`.
- Save captures graph revision; when revision advanced, rebase upload stabilization as a preconditioned media patch onto the latest semantic snapshot; save reconciliation only overlays active-lease runtime overlays explicitly excluded by the serializer.
- After board attachment or execution lease expires, old async completions are rejected: no materialize, cancel, or projection into the new session.
- `features/board` stays independent: `board/domain` owns only schema, node/connection model, registry, sizing, aspect ratio, fusion blend; `board` never depends on canvas runtimes, Vue Flow adapters, image tool sessions, or page shells; canvas hydrates/exports snapshots via the `board` public seam, never the reverse.
- Dirty/retry/conflict state drives network/re-auth automatic recovery without a persistent autosave status block; actionable save failures surface via Toast.
- The World Capture reflow type contract has zero 3D/Fabric/Vue dependencies; a future producer must enter through graph-editing intents (creation / media-input mutation), never by writing Vue Flow projections or `CanvasGraphStore` internals.

## Non-goals

- No Vue Flow graph as domain truth; `Canvas Node` / `Canvas Connection` / `BoardSnapshot` are facts, `Flow Node` / `Flow Edge` / native events are adapter representations.
- No callback bags, compat exports, or escaped lifecycle cleanup commands.
- No page-scattered interaction refs, native event callbacks, or keyboard/lifecycle wiring.
- No graph editing-owned overlay state; no recomputed creation coordinates after viewport changes.
- No page-authored controls or route-local positioning classes.
- No graph runtime state source inside status controls.
- No content fingerprint or Task ID as idempotency key; key is `client_action_id`.
- No Canvas-disabled state or permanent workflow shutdown on provider degradation.
- No boolean applying flag or unguarded late completions.
- No live 3D capture path; the World Capture seam is a type contract only, with no 3D producer, no consumer wiring, and no graph/projection writes.
